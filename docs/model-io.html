模型的输入和输出到底长什么样

用那个真实钓鱼地址（0xca2909…，200 笔交易）现场演示。下面展示它第 30~41 笔的窗口，点任何一列，看这个事件的五个编号怎么查表变成向量、模型又对它输出了什么概率。先记住一句话：模型不输出"是不是骗子"，它只输出"每个位置该是什么"的概率分布——风险分是之后算出来的。

总览

维度旅程：五步变形

[1, 200] ×5张
输入: 整数表
[1, 200, 80]
查表拼接
[1, 200, 64]
压缩+Transformer
[1, 200, K] ×3张
输出: 概率分布
[1, 200] → [1]
(模型外)打分

1=这批只有1个用户；200=序列长度；K=各预测头的类别数(类型3/间隔9/个人金额8)。模型只负责中间三步。

第①步

输入：几张 [1×200] 的整数表（这里展示第30~41列）

竖着一列 = 一个事件，横着一行 = 一路字段。格子里就是桶编号。点一列试试 → 后面所有环节跟着变。
第②步

查表拼接：一列编号 → 一个 80 维向量

选中列的每个编号去查各自的 Embedding 表（表内数值是训练学出来的），得到的向量拼接在一起：
type 32维
gap 16维
gamt 8维
pamt 16维
hour 8维
↓ 拼接 = 80 维 → Linear(80→64) 压缩 ↓
该事件的 64 维向量（进 Transformer 的最终形态）

200 个事件都这么处理 → [1, 200, 64]。然后过 2 层 Transformer——形状不变，还是 [1, 200, 64]，变的是内容：每个位置的向量吸收了上下文（它前后发生了什么、隔多久）。

第③步

输出：模型对这个位置的三份概率分布（真实数值）

每个预测头输出一张 [1, 200, K] 的表。取选中位置那一行、过 softmax，就是下面的概率条。红条 = 真实答案落在的那一档。
第④步

模型之外：概率 → 惊讶度 → 风险分

这一段发生在模型外面，全是确定性计算，维度一路收缩：
操作形状变化本例真实数值
惊讶度 = −ln(真实答案的概率)[1,200,K] → [1,200]—
z 归一化（减同难度均值÷标准差）[1,200] → [1,200]—
池化（本数据: 全序列平均）[1,200] → [1]200个z平均 = 1.882
对阈值（白样本p99）[1] → 判定1.882 ≥ 1.261 → 命中⚑（确为真实钓鱼地址）
防晕锚点：输入是"编号表"、输出是"概率表"，两者的前两维都是 [用户数, 序列长度]——模型自始至终在做"逐位置的选择题"，从没做过"这个人是不是骗子"这道题。黑白之分是我们统计它"答题惊讶程度"后加出来的。

本页所有数值来自真实模型 eth_outputs/model.pt 对真实钓鱼地址 0xca2909… 的推理输出（含 softmax 原始概率）， 由 export 脚本导出，未做修饰。注：全流程批量打分用"步长遮罩"，与本页单点遮罩的惊讶度数值有微小出入，属正常。 配套：交互追踪器 tracer.html · 零基础教程 tutorial.html。
