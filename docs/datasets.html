先回答一个关键问题：为什么一半数据是"仿真"的？

因为真实的银行反欺诈数据在法律上不可能公开。账户流水、客户行为日志受《个人信息保护法》《数据安全法》和金融监管约束——全世界任何一家银行都不能把带欺诈标注的客户数据放到网上。所以公开领域能拿到的"真实"只有两类：区块链（链上交易天然全网公开，本页的以太坊钓鱼就是）和极少数高度脱敏的数据（往往脱敏到没有账户序列可言）。这是整个反欺诈研究领域的共同现实，不是本项目的选择。

仿真数据是怎么造出来的？主流做法叫"基于智能体的仿真"（agent-based simulation）：先从真实机构的聚合统计（交易量分布、金额分布、商户结构——这些不涉及个人隐私，可以拿到）建一个虚拟世界，里面放几千个虚拟客户，每人有自己的收入、消费习惯、活跃时段，让他们"生活"几个月到几年产生流水；然后按已知的欺诈模式（盗刷剧本、洗钱的分散-归集模板）往里注入欺诈行为。IBM、瑞典的研究组做的 TabFormer/BankSim/PaySim/AMLSim 都是这个路数；我们自研的 temporal/rich 同理，只是把"信号设计权"抓在自己手里用于机制验证。

仿真的价值与风险都要说清：价值是①有完整标注（虚拟世界里谁是骗子当然知道）②可控可复现③能造出"我们知道答案"的考卷来验证方法机制。风险是仿真质量直接决定结论可信度——PaySim 就是反面教材：它的欺诈是随机注入的、没有行为纹理，导致连全标签模型都分不开（0.61），我们据此把它判为不可用。

所以本项目的证据链刻意分了三级：合成数据（自研）证明机制成立 → 拟真数据（IBM 等机构级仿真）证明工程可迁移 → 真实数据（以太坊）证明效果真实存在。最终效果以你的业务真实数据为准——这也是为什么整套流水线的终点设计是"接入真实数据后半天摸底"。

结果出处：EXPERIMENT_MEM / ARCH_REPORT / IMPROVEMENT_REPORT / OPEN_DATA_SURVEY 等报告，均可在仓库复现。 oracle = 用全部标签训练的对照模型，代表该数据的信号上限。
