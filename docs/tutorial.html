第 0 章

问题与核心思路

为什么标签稀缺，以及一个保安的比喻

0.1 要解决什么问题

银行/支付平台想从海量用户里找出欺诈账户：被盗号的、做套现的、帮骗子收款的。传统机器学习的做法是"给我一堆标好'这是骗子/这是好人'的样本，我学出一个分类器"。但现实是：

  • 欺诈标签极其稀缺——确认一个欺诈案件要经过报案、调查、定性，能拿到的黑样本往往只有几十个，而用户有几十万；
  • 欺诈手法持续变化——就算标了 1000 个去年的案子，今年骗子换了剧本，分类器认不出来；
  • 正常用户的数据倒是要多少有多少，而且几乎都是真正常（欺诈率通常只有 0.1%~1%）。

所以问题变成：只有一大堆"基本都是好人"的行为数据、几乎没有欺诈标签，怎么把骗子挑出来？

0.2 核心思路：保安认熟客

比喻

一个小区保安干了十年，从没人教过他"小偷长什么样"，但他能一眼看出不对劲的人。为什么？因为他太熟悉"正常"了：住户几点出门、快递员怎么走、访客什么节奏。小偷可以穿得人模人样，但他在楼道里的停留、张望、折返，处处违反保安脑中的"正常剧本"——他不需要认识小偷，他只需要熟悉正常。

本方案就是把这个保安换成一个小型神经网络：

  1. 只用正常用户的行为数据训练一个"预测行为"的模型——让它做几十万道"看了前面的操作，猜下一步是什么"的预测题，做多了它就掌握了正常行为的规律（术语叫"行为语法"）；
  2. 拿它去看待检用户：正常用户的行为它猜得准；欺诈者的行为处处出乎它意料——把"意外程度"累计起来就是风险分；
  3. 风险分超过阈值的，连同"具体哪几步可疑"一起推给人工审核。

术语备注：这类方法学名叫"自监督异常检测"（self-supervised anomaly detection）。说"无监督"是因为全程不用欺诈标签；说"自监督"是因为训练时的标准答案（下一个事件是什么）就藏在数据自己身上，不需要人标。

第 1 章

数据长什么样

先认识原材料：行为序列

原材料是行为序列：把一个用户在一段时间内做过的所有事，按时间顺序排成一列。每件事叫一个事件，带着"什么类型、什么时间、多少钱、成没成功"等字段。

真实例子 · 一个正常用户(白样本)的序列片段 
{"user_id": "N00010", "label": 0, "events": [
  {"type": "登录",   "t": "2024-06-03 08:00:00", "result": "成功"},
  {"type": "查余额", "t": "2024-06-03 08:27:00"},
  {"type": "消费",   "t": "2024-06-03 08:36:00", "amount": 167313},
  {"type": "消费",   "t": "2024-06-03 09:05:00", "amount": 128780},
  ... ]}

读法：这个人 8 点登录，27 分钟后查余额，9 分钟后消费一笔……label:0 表示他是白样本（正常人）。训练时我们只用这样的数据，且训练过程根本不看 label。

真实例子 · 一个欺诈用户(黑样本)的关键片段 —— 盗号剧本 
...前面 19 天都是正常购物消费...
{"type": "设备变更", "t": "01-20 20:00:58"}          ← 换了新手机
{"type": "改密码",   "t": "01-20 20:01:42"}  +44秒   ← 紧接着改密码
{"type": "改限额",   "t": "01-20 20:04:11"}  +149秒
{"type": "转出",     "t": "01-20 20:05:13", "amount": 1238}  +62秒
{"type": "解绑卡",   "t": "01-20 20:09:10"}  +237秒

肉眼就能看出问题：20 分钟内连续做了 5 个敏感操作。正常人也会改密码、也会换设备，但那些操作彼此隔着几小时到几天。方案要做的就是让机器自动发现这类"违反正常节奏"的模式——而且不止时间节奏这一种。

名词小结：白样本=正常用户；黑样本=欺诈用户（只在最后评估效果时用到，训练不用）；序列=一个用户的全部事件按时间排列。

第 2 章

编码：把行为变成数字

神经网络只认数字，每个事件要变成一个向量——本章手算全过程

2.1 思路：每个事件拆成 8 路字段，各自"分桶"成编号

连续值（金额、时间间隔）不直接用原始数字，而是切成有限个"桶"，事件只记桶号。下面拿真实事件手算一遍。

手算例子 · N00010 的那笔消费 167,313 元, 08:36, 距上一事件 9 分钟

字段 1 · 事件类型 → 查字典

字典: {登录:0, 查余额:1, 改限额:2, 改密码:3, ..., 消费:9, ...}
"消费" → type = 9

字段 2 · 全局金额桶 → 和全体用户比

把训练集所有金额排序，取 7 个等分位点当桶边界（这份数据算出来是 35,094 / 58,825 / 75,367 / 116,025 / 139,760 / 158,006）：

167,313 > 158,006（最后一个边界） → 全局桶 = 7（全社会视角的最高档）

字段 3 · 个人金额桶 → 和他自己比（全方案最值钱的特征）

先算他本人历史金额的中位数 = 66,285，再算这笔是几倍，按 [0.25, 0.5, 1, 2, 4, 8] 倍切档：

167,313 ÷ 66,285 = 2.52 倍 → 落在 [2, 4) 区间 → 个人桶 = 5

为什么值钱：同样"转出 5 万"，对基线 500 元的人是 100 倍（顶格），对基线 5 万的人是 1 倍（平常）。全局桶看不出这个差别，个人桶专门编码"这对他自己正不正常"。

字段 4 · 间隔桶 → 距上一事件多久

桶边界: [≤1分, 1-5分, 5-30分, 0.5-1时, 1-6时, 6-24时, 1-7天, >7天, 首事件]
间隔 9 分钟 → 落在 5-30分 → 间隔桶 = 2

字段 5 · 时刻 → sin/cos 连续编码

钟表是圆的（23 点和 1 点很近），所以用三角函数而不是桶：

8:36 → 8.6 时 → sin(2π×8.6/24) = 0.78, cos(2π×8.6/24) = −0.63

字段 6~8 · result / channel / ip_change → 有则编码，无则填 0

这笔消费没有 result 字段 → res = 0（"不适用"）；channel、ip 同理 → 0

"不适用"不是数字零，是查表得到的一个可学习向量——这个设计让"登录"和"消费"这种字段完全不同的事件能进同一条序列（统一 Schema）。

2.2 桶号 → 向量：查表拼接

每路桶号去查各自的 Embedding 表（一张"编号→向量"的查询表，表里的数值是训练中学出来的）：

type=9 → 查 类型表(12行×32维) → 32 维向量
res=0 → 查 结果表(3×4) → 4 维
ch=0, ip=0 → 渠道表/ip表 → 8+4 维
全局桶=7 → 查 全局金额表(8×8) → 8 维
个人桶=5 → 查 个人金额表(8×16) → 16 维
间隔桶=2 → 查 间隔表(9×16) → 16 维
时刻 → (0.78, −0.63) → 线性层 → 8 维
──────────────────────────────────
拼接 = 96 维 → 线性压缩 → 该事件的 64 维向量

一个用户 70 个事件 → 一个 [70 × 64] 的矩阵，这就是模型的输入。

为什么分桶而不用原始数值？三个原因：① 后面这些桶号既是输入也是考题答案——"猜金额档"是 8 选 1 的选择题，良定且稳健；② 金额是长尾分布，原始值会被极端值主导；③ 分桶后查表，让模型给"大额"学出丰富的语义，而不是一个干巴巴的数。分位数分桶还天然免疫量纲（元/分/美元都一样）。

第 3 章

训练：模型怎么学会"正常"

做几十万道预测题，答案就在数据里

3.1 模型本体：一个小 Transformer

Transformer 你只需要知道一个直觉：它读一条序列时，能同时看到所有位置并自动学会"该重点看哪里"（注意力机制）。本方案的模型很小——2 层、约 9 万参数，普通笔记本 CPU 几分钟训完。判别力不来自模型大小，来自练习方式。

3.2 练习方式：预测题

真实例子 · 一道训练题（自回归式）
已见: [登录·成功·08:00] → [查余额·+27分] → [消费·167,313·+9分]
题目: 请预测第 4 个事件的 ①类型 ②间隔档 ③结果 ④个人金额档
标准答案(就在数据下一行): [消费 · 128,780 · +29分]

模型对每问输出一个概率分布（比如"类型：消费 41%，查余额 22%，登录 15%……"）。答错多少，就按错误程度微调内部参数。一个用户 70 个事件就是 69 道题，几千个用户 × 几十轮 = 几十万道题做下来，模型就"见惯了"正常人的行为规律：会话内小间隔的事件多是消费/查余额、改密码前通常隔了几小时、金额一般在个人基线 0.5~2 倍之间……

关键：全程没有用任何欺诈标签——考题和答案都来自正常数据自己。这就是"自监督"。

3.3 三种出题方式（按数据类型选，实验裁决的对照表）

数据类型出题方式一句话原因实验得分
操作流（App 日志）自回归：只看历史猜下一步（+时间偏置注意力）盗号是因果链，"下一步"可预测；只看历史让攻击起点惊讶最大化0.984
资金流（转账流水）完形填空：随机遮 15% 事件用前后文猜回异常是账户整体风格，双向看即可0.904
消费流（卡交易）遮字段：只遮金额、类别可见，学"这类消费该花多少钱"下一笔买什么本质随机；欺诈藏在"字段搭配不对"里0.886
例子 · 遮字段式出题（消费流）
已见: [类别=杂货店, 时刻=23:40, 距上笔=2小时, 金额=???]
题目: 猜金额档。 (正常人深夜杂货店消费是小额 →
若真实金额是本人基线的 12 倍 → 模型大吃一惊 → 这就是欺诈信号)

这个选择不是拍脑袋：在真实卡数据上，用错出题方式（完形填空）只有 0.557，换成遮字段直接到 0.886——出题方式必须匹配数据类型，第 7 章有完整数据。

3.4 "只用白样本"怎么保证？——不用保证

现实中你拿到的是 unlabeled 数据，里面混着约 0.1%~1% 的欺诈。实验专门测过往训练集里掺欺诈：

训练集混入欺诈比例0%1%5%10%
最终 AUC0.96050.96470.96710.9598

混 10% 都几乎无损——因为欺诈模式在几十万道题里只占约 1%，模型来不及把它学成"正常"。所以 unlabeled 数据直接当白样本用即可（唯一边界：污染超过 ~15% 时会开始失效，第 7 章有这条边界的实证）。

第 4 章

打分：从"惊讶"到风险分

三步走，其中第二步是整个项目摔得最疼的地方——手算全过程

4.1 第一步 · 逐位置算"惊讶度"

拿训练好的模型去看待检用户：每个位置让模型预测，对照真实发生的事件，用交叉熵量化惊讶程度——就是"模型给真实答案的概率取负对数"：

真实例子 · 同一个模型的两次真实输出（含手算）

局面 A —— 白样本购物会话中的一个位置，真实事件是消费：

消费
27.2% ✓ 真实答案
登录
25.5%
查余额
18.2%
惊讶度 = −ln(0.272) = 1.30 ← 猜得准, 很平静

局面 B —— 黑样本爆发链中（前 149 秒是改密码），真实事件是改限额：

消费
28.9%
登录
25.5%
改限额
1.25% ← 真实答案
惊讶度 = −ln(0.0125) = 4.38 ← 大吃一惊

模型以为小间隔的上下文里该是购物会话，结果冒出个改限额——1.30 vs 4.38，欺诈位置的惊讶度是正常位置的三倍多。

4.2 第二步 · 难度归一化（不做这步，结论是反的）

血泪教训：直接把每个位置的惊讶度取平均当风险分，实测 AUC 只有 0.32——比抛硬币还差，方向反了。原因叫"熵混淆"：有的位置天生难猜（隔了 6 小时之后干什么，谁都猜不准），有的天生好猜（会话内下一步八成还是购物）。而黑样本的爆发窗口恰恰全是小间隔——形态像购物会话，"天生好猜"，平均下来黑样本反而显得更正常。

修法：用白样本统计出"每种间隔难度下，正常人的惊讶度均值 μ 和标准差 σ"（下表是真实统计值），然后每个位置换算成标准分 z：

间隔桶≤1分1-5分5-30分0.5-1时1-6时6-24时
正常人惊讶度均值 μ1.711.711.722.232.312.34
手算例子
z = (该位置惊讶度 − 同难度正常均值μ) ÷ 同难度标准差σ

局面B: 间隔桶=1-5分, 惊讶度4.38 → z = (4.38 − 1.71) ÷ 0.67 = +3.98
另一位置: 间隔桶=0.5-1时, 惊讶度2.40 → z = (2.40 − 2.23) ÷ 1.13 = +0.15

第一个位置比同等难度下的正常人多惊讶 4 个标准差——高度可疑；第二个虽然惊讶度绝对值不低，但那个难度下人人如此——正常。z 分回答的不是"惊讶多少"，而是"比同等难度下的正常人多惊讶多少"。这一步把 AUC 从 0.32 反转到 0.76。

4.3 第三步 · 汇总（池化）：一串 z 分 → 一个风险分

规则：欺诈是局部的（盗号只污染序列一小段）就取 z 分最高的 5 个位置平均（top-5）；欺诈是整体的（钓鱼账户每笔都是作案）就全序列平均。

手算例子 · 两个真实用户的最终风险分
黑样本 B_0291 的 top-5: 4.65(解绑卡) 4.13(绑卡) 3.98(改限额) 3.81(借款) 3.70(借款)
风险分 = (4.65+4.13+3.98+3.81+3.70) ÷ 5 = 4.05

白样本 W_0485 的 top-5: 3.73(借款) 2.02(解绑卡) 1.72(绑卡) 1.69(绑卡) 1.42(设备变更)
风险分 = (3.73+2.02+1.72+1.69+1.42) ÷ 5 = 2.12

两个细节：① 白样本也有一个 3.73 的单点高分（会话里巧合夹了笔借款）——这就是取 top-5 而不是 top-1 的原因：单个巧合拉不动均值，成串的异常才能过线；② 黑样本的 top-5 里三个直接落在爆发链上——这 5 个位置就是给审核员的"可疑操作清单"，分数自带证据。

第 5 章

阈值与输出：分数怎么变成决策

阈值不是拍脑袋，是白样本分位数定的

现在每个用户一个风险分，在哪切一刀判"可疑"？方法：拿一批白样本算分，取它们的 99 分位数当阈值——数学上保证只误伤 1% 的正常用户。

真实例子 · 这一刀切下去发生什么
白样本分数的 99 分位 = 3.52 ← 阈值
B_0291 = 4.05 > 3.52 → 命中 ⚑（连同 top-5 可疑位置推给审核）
W_0485 = 2.12 < 3.52 → 放行

这一刀实测：误报率 1%，抓住 70.8% 的黑样本。想抓更多就把刀左移——用误报换召回，和银行评分卡的运营方式完全一致。

三条运营规则：① 按用户活跃度分组各定各的阈值（活跃者与低频者分数分布不同，一刀切会系统性冤枉一群人）；② 每月用新白样本重算阈值（防用户行为漂移）；③ 输出只做排序+人工审核，不自动冻结——附带的 top-5 位置让审核员几分钟就能定位问题。

第 6 章

融合：模型原理上吃不到的信号

一条拿真实数据换来的机制规律

有一类信号永远不会以"惊讶"的形式冒出来：账户级的静态比例特征。例如"打款方里首次出现的陌生账户占比"——钓鱼收款账户这个比例接近 100%（全是受害者，都是生面孔）。但如果把它做成字段塞进模型，模型学会"这类账户的对手方就是全新的"之后预测得很准、不惊讶，信号在预测通道里消失了。

正确用法：这类特征直接算出来当"第二个分数"，和模型的惊讶分做排名融合（各自排名加权平均）。

真实例子 · 以太坊钓鱼数据(全真实)上的四行对照
做法AUC误报1%时的召回
模型惊讶分（单独）0.903514.7%
"首次对手方占比"特征（单独）0.8168—
把该特征塞进模型当字段 ✗0.9041（白费）—
两个分数排名融合 ✓0.928144.9%（翻 3 倍）

同一个信号，走错通道无效，走对通道离"用全部标签的上限"(0.934)只剩 0.006。

规律：信号分两类——模式类（顺序、搭配、节奏的异常）交给模型的预测通道；聚合类（比例、计数、画像）走分数融合通道。落地采集字段时，"收款账号是否首次出现"属于必采。

第 7 章

实验证明：数据说话

怎么测的、测出什么、包括失败在内的全部结果

7.1 评测方法：先说清怎么算"分得开"

  • 切分：白样本 80% 训练 / 20% 留出；黑样本全部只进测试集。模型打分时不知道谁黑谁白，打完才拿标签"阅卷"；
  • AUC：核心指标，含义是"随机抽一个黑、一个白，黑的分数更高的概率"。0.5=抛硬币，0.7=能辅助排序，0.9+=优秀，1.0=完美分开；
  • oracle 参照（开卷考生）：每个数据集另训一个拿着全部标签学的传统模型，它的分数≈这份数据的理论上限。我们的方法是"闭卷考生"——看它离开卷差几分，才知道方法好坏；开卷都考砸的卷子，说明数据本身没信号。

第 8 章

常见疑问 FAQ

新读者最常问的八个问题

一个欺诈标签都不用，那你们的 AUC 是怎么算出来的？

训练不用标签，阅卷必须用——评测数据集自带标注（合成数据是造的时候就知道、开源数据带官方标注），打完分再对答案。落地到无标签的真实环境时，评估需要攒几十个历史确认案件当"答案"；一个都没有就先上线做排序，用人工审核结果当答案。

为什么不直接聚类（把用户分成几堆，看哪堆是骗子）？

试过，这正是本项目的起点。无监督对比学习+聚类在同类数据上分离比 ≤1.15 且越训越差——数学上它的目标（把所有人互相推开）和"黑白各聚一堆"冲突。这次失败是转向现方案的原因，有完整实验记录。

骗子知道了这套逻辑，能绕过吗？

比绕过规则难得多。他要同时做到：操作节奏像正常人、金额符合受害者本人的历史惯例、收款方有历史记录、不触发失败登录——相当于"表现得像受害者本人"。理论上放慢节奏能稀释时序信号（对抗漂移，未实测，靠定期重训缓解），但金额和对手方两路信号很难伪装。

数据格式和例子里不一样怎么办？

编码是"固定骨架+自动适应"：词表、金额分位点从数据自动学；字段缺了填"不适用"桶；间隔桶边界按数据的时间粒度配置。配套工具（fraud_pipeline.py）五条命令完成接入，只有"数据根本不是事件流"（比如一行一用户的汇总表）才需要换方法。

模型多大？要 GPU 吗？

2 层 Transformer，约 9 万参数（普通图片分类模型的千分之一），笔记本 CPU 上几分钟训完、打分毫秒级。方案的力量在目标函数和打分设计，不在算力。

攒到欺诈标签之后呢，这套就没用了？

分三段：标签 <10 个，纯本方案；10~50 个，标签只用来校准融合权重和阈值（实验证明拿去微调模型反而更差）；50+ 个，训一个监督模型接管主判别（能到 0.996），本方案转为它的输入特征 + 新型欺诈兜底——监督模型只认识见过的骗术，没见过的还得靠"惊讶"。

误报了怎么办？会不会冻结正常用户？

方案定位是"排序+证据+人工审核"，不自动处置。阈值定在白样本 99 分位=误报率 1%，且按活跃度分组分别定，审核员拿着 top-5 可疑位置几分钟即可复核。

最少要多少数据才能起步？

经验值：1000+ 用户、每人 ≥10 个带精确时间戳的事件，即可训练；评估另需几十个已确认案件。数据到位后半天摸底、当天出分。
